1. 連携構成図

geo_webview の役割は 「QGIS を Web 配信側に変える」 ことです。 GIS データの編集・スタイル設定は QGIS が最適な環境であり、このプラグインは その成果をそのまま Web へ持ち出します。

[QGIS プロジェクト]  レイヤ・スタイル(.qml)・レイヤツリー・視点・テーマ
        │  geo_webview が .kasc + DATA/ へエクスポート
        ▼
[.kasc + DATA/ パッケージ]  + エンジン本体(KASUGAI Canvas web/)
        │  Cesium / MapLibre / OpenLayers / Leaflet で再生
        ▼  静的ホスティングへ配置
[ブラウザの WebGIS]  ← サーバーレス（QGIS・専用サーバー不要）
  • 主機能 = サーバレス配信: 表示中レイヤと QGIS スタイルを .kasc+DATA/ に書き出し、エンジン（KASUGAI Canvas web/）と一緒に 任意の静的ホストへ置くだけで WebGIS として配信できる。 再生に QGIS 側サーバーは不要
  • 補助 = 内蔵 HTTP サーバー: /kasugai 起動 API、エクスポート物の /export-data/ 配信、画面共有（/present・/screenshot）、 受領履歴（/received）、Canvas web/ の静的フォールバックを提供する。 ※OGC サービス（WMS/WMTS/WFS）は v3.29.0 で廃止

連携方針（対応クライアント）

geo_webview の連携方針は、プレイヤーを KASUGAI Canvas に一本化 （Cesium・MapLibre・OpenLayers・Leaflet のマルチエンジン構成。 KASUGAI 側で統一開発済み・?engine= で切替）し、 Re:Earth Visualizer をサブとすることです。

配信ルートは2系統です。高機能ルートは起動中の KASUGAI Canvas ローカルサーバー（既定 :8510）の専用 API でプロジェクト登録・画面切替 まで行い、通常ルートは内蔵 HTTP サーバーとサーバレス Web 配信で Canvas アプリなしでも即座に Web 化します （「再生経路（3段フォールバック）」参照）。

① セット開発のプレイヤー群

QGIS からエクスポート/配信されたデータ・スタイルを取り込んで再生するクライアント。geo_webview はこのプレイヤーの QGIS 側受け皿（配信元）として開発を進めています。

連携先 経路 連携の形
KASUGAI Canvas /kasugai（.kasc+DATA/） 統合プレイヤー（主）。QGIS レイヤツリーを .kasc+DATA/（ベクター＋.qml スタイル）として出力し、起動中の KASUGAI へ外部プロジェクト登録・表示切替。パネルの Export ボタンはファイル出力のみ、▶ Open / GET /kasugai?engine= / kasugaiExport ブリッジは登録・起動まで行い、同じ .kasc+DATA/ を全エンジンで再生。EXE 込みインストールでは rclone・自動更新・ファイル保存・.kasc 関連付けも利用可
② その他クライアント・外部サービス
連携先 経路 連携の形
Re:Earth Visualizer（geo_suite） kasugai_canvas_*.zip（qgis: インスペクタ行で取込）・/export-data/ サブ（KASUGAI Canvas と同じ Cesium ベース）。下記「Re:Earth Visualizer（geo_suite）への対応方針」参照
ArcGIS 系 .kasc+DATA/ ファイル受け渡し → ArcGIS 側（SDK）の独自実装を外部静的ホストで配信（GitHub Pages/Cloudflare/Vercel/自前サーバ等。ArcGIS Online 上では動作不可） 下記「ArcGIS 系への対応方針」参照
Re:Earth Visualizer（geo_suite）への対応方針

Re:Earth Visualizer は KASUGAI Canvas と同じ Cesium ベースのサブプレイヤー として位置づけます。geo_webview は kasugai_canvas_*.zip（パネルの ZIP ボタンまたは index.html からダウンロードしたエクスポート一式。* は CDN チャンネル名）と /export-data/ 経由のファイル・.qml スタイル配信で供給し、取込は geo_suite 側の qgis: インスペクタ行（ZIP の URL 指定）が担います。3D 表現は Cesium ベースの KASUGAI Canvas（主）・Re:Earth Visualizer（サブ）に集約して開発します。

詳細: geo_webview 連携方針（INTEGRATION_JP.md）

ArcGIS 系への対応方針
  • ① ArcGIS Online 上ではカスタムコードを実行できず、本系統の機能は実現不可能
  • ② Cesium 等のエンジンと同等品を作る場合 — Canvas 側のコード資産は SDK が異なり流用できないため、データ構築を含めて一からの開発が必要（3D は 3D Tiles→I3S 変換パイプライン経由が前提・ライブ 3D Tiles URL は対象外。参照できるのは .kasc 仕様と同一 OSS ライブラリのみ）
  • ③ ArcGIS のセキュリティ（管理環境）内でカスタム WebGIS を動かすなら Enterprise 11.0+ の ExB カスタムウィジェットが唯一の経路 — それ以外はすべて外部ホスト前提のモデルとなり、導入の意義がない
