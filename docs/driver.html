QGIS Live Driver

Harnessから独立した汎用制御プラグイン — QGIS側の「手」。

qgis-plugin/qgis_live_driver/ は UIを持たない制御専用プラグインで、実行中QGISを外部から遠隔操作する面を提供する。 QWebEngineView を持たないため、WebEngineを使わない任意のQGIS環境・ 任意の他プラグインに対しても使える汎用部品。

pyeval でQGISプロセス内の任意Pythonを同期実行できるため、 PyQGISで書ける操作は全て制御可能: レイヤー/プロジェクト操作、 キャンバス、メニュー/アクション、qgis.utils.plugins 経由の他プラグイン、 Processing、QgsSettings、任意widgetの grab() による画像化 等。

さらに status/open_plugin/reload_plugin/bridge_call のnamedコマンドと、 plugin_id による他プラグインへのコマンド転送(ハブ機能)を持つ。 plugin_id 付きの eval/pyeval/screenshot/devreload は 対象プラグインのLiveDriverへ転送され、結果は呼び出し元に返るため、 このドライバ1箇所(またはHTTPポート1本)で全プラグインを制御できる。 bridge_call はbridgeメソッドをプロセス内で直接呼ぶため、 WebChannelを通らずJSレンダラー飢餓中でも動作する。

接続面(4系統・全て同じdispatchへ)

  • ファイルJSONL — commands.jsonl 追記 → QTimerが実行 → results.jsonl 返却。 言語非依存の最下位輸送層
  • HTTP REST — POST 127.0.0.1:<port>/api/pyeval {"code":"..."} 等。 MCPを知らないfunction calling系AI・curl・自作エージェント向け
  • MCP Streamable HTTP — POST 127.0.0.1:<port>/mcp(JSON-RPC)
  • MCP stdio — 同梱 mcp_stdio.py をspawnするだけ(stdlibのみ、spawn側にQGIS/Node不要)

②③はプラグイン内蔵の http.server(stdlibのみ・127.0.0.1・空きポート自動選択)が提供。 ワーカースレッドが受けた命令は driver.submit() でメモリキューに入り、 GUIスレッドのQTimerがファイルJSONLと同じ要領で実行する(dispatchは1本に統一)。 ポート番号等の接続情報は ~/.qgis-live/<pid>-qgis_live_driver.json に書き出され、 クライアントはここから自動検出できる(QGIS_LIVE_REGISTRYで変更可)。

外部公開(Copilot Studio等からの接続)

/mcp は Copilot Studio が対応する Streamable HTTP transport 互換だが、 既定では 127.0.0.1・認証なしのためクラウドからは到達しない。 以下の手順で公開できる。

1. APIキー認証と公開ツールの絞り込み(QGIS起動前にenvを設定)

$env:QGIS_LIVE_API_KEY = "<ランダムなキー>"
# 推奨: 公開ツールを限定。pyevalは任意コード実行のため除外
$env:QGIS_LIVE_TOOLS = "status,screenshot"
npm run live:ensure
  • 親シェルのenvは live:ensure → powershell → Start-Process 経由でQGISへ引き継がれる。既にQGISがlive中の場合は再起動が必要(envは起動時に読む)
  • QGIS_LIVE_API_KEY 設定時は Authorization: Bearer <key> / X-Api-Key: / api-key: のいずれかのヘッダを要求(不一致は401)。/api/health のみ無認証
  • QGIS_LIVE_TOOLS はコマンド種別名のカンマ区切り(qgis_前置も可、*または未設定で全許可)。/mcp の tools/list・tools/call と /api/* の両方に効く
  • 有効状態は ~/.qgis-live/<pid>-qgis_live_driver.json の http_auth / http_tools / mcp_url で確認できる(キー自体は書き出さない)

2. HTTPSで公開(トンネル)

Copilot Studioはクラウドのため公開URLが必要。ローカルポートをトンネルする:

devtunnel host -p <port> --allow-anonymous
# または
ngrok http <port>

(TLS終端とFQDN払い出しはトンネル側が担い、認証は /mcp 側のAPIキーが担う)

3. Copilot Studio 側の設定

エージェントの Tools → Add a tool → New tool → Model Context Protocol で MCP onboarding wizardを開き、Server URL に https://<トンネルFQDN>/mcp、 認証に API key を選んで QGIS_LIVE_API_KEY の値を入力する。 generative orchestration が有効なエージェントが必要。 追加後は qgis_status 等がツールとして使える。

REST面を使う場合は Power Apps カスタムコネクタ経由で /api/* を包む方法もある。

Harnessなしでの単独導入

Driverの利用にこのリポジトリは要らない:

# このリポジトリからなら一括deploy(任意)
powershell -ExecutionPolicy Bypass -File scripts/deploy-plugin.ps1 -Copy

# 手動でも可: qgis-plugin/qgis_live_driver/ を
# python/plugins/qgis_live_driver/ へコピーし、QGISのプラグイン管理で有効化

あとは WEBENGINE_LIVE_DIR を設定した状態でQGISを起動するだけで、 live dir(<WEBENGINE_LIVE_DIR>/qgis-<pid>/qgis_live_driver/)と レジストリJSONが作られ、上記4系統のいずれでも接続できる (未設定なら何もしない無害なプラグイン)。

セキュリティ: pyeval は任意コード実行。開発専用であり エンドユーザーへの配布物に含めてはいけない。 HTTPサーバは 127.0.0.1 のみにバインドする。詳細・制御範囲・制約は qgis_live_driver/README.md を参照。
